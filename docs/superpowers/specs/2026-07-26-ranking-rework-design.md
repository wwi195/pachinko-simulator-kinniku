# ランキング方式変更 設計

## 背景・目的

現行のランキングは「退店時点の持ち玉数」をセッション単位で記録している（`showSettle()` 内 `recordRanking(balls)`）。これを「RUSH終了時点の獲得出玉」単位の記録に変更する。1プレイセッション中にRUSHが複数回発生した場合、それぞれのRUSHが個別のランキング対象になる（セッション最終成績ではなく、単発RUSHの成績を競う形）。

## 記録トリガーと対象

- 記録タイミングは `endRush()` 内。RUSH終了時にすでに計算済みの `totalBalls`（そのRUSHの獲得出玉、`rushStock` から算出）と `finalRenchan`（連チャン数）を使ってその場で記録する。
- 闇パチ中（`S.limitPassed` 成立後）に終了したRUSHは、これまでの「闇パチ経由は対象外」ルールを踏襲し、ランキング記録の対象外とする。
- `showSettle()`（精算画面）側の `recordRanking` 呼び出しと関連するランキング表示ブロックは削除する。ランキング記録・表示はRUSH終了時点に一本化する。

## データ形式

- localStorageキーは既存の `kinnikuRankingV1` を継続使用する。
- 保存する1エントリの形式を `{balls, renchan, date}` に変更する（`balls`=獲得出玉、`renchan`=連チャン数、`date`は既存同様の表示用日付文字列）。
- 初回読み込み時（`loadRanking()`）、既存データが旧形式（`renchan`フィールドを持たないエントリ）と判定された場合は、リストごと破棄して空リストから開始する（新旧混在を避けるため）。
- ソートは引き続き `balls` 降順、上位10件のみ保持（`recordRanking` の既存トリム挙動を維持）。

## 表示

- `renderRankingList()` の各行に `連チャン数` を追加表示する（例: `7500玉 (5連)`）。既存の日付・ランクイン🆕ハイライトの表示ロジックは維持する。
- `tmRushEnd()`（RUSH終了画面）に、記録直後のランキング表示（1〜10位＋新規ランクイン🆕ハイライト）をその場で追加する。`endRush()` は `recordRanking()` の戻り値（`list, entry, madeList`）を使って `tmRushEnd()` にランキングHTMLを渡す。
- `showSettle()` からランキング表示ブロック（🏆見出し・闇パチ除外メッセージ・ランキングリスト）を削除し、持ち玉・換金・投資などの通常精算内容のみ残す。
- `showRanking()`（🏆ボタンから独立して呼び出す閲覧画面）の説明文を「RUSH終了時の獲得出玉（闇パチ中終了を除く）」に更新する。

## 影響範囲外（変更しないこと）

- ランキングの保持件数（上位10件）、ソート基準（`balls` 降順）は変更しない。
- `recordRanking` の「闇パチなら記録しない」という条件分岐の構造自体は維持し、判定対象を「セッション全体」から「そのRUSH終了時点の `S.limitPassed`」に読み替えるのみ。
- 画像・演出フロー、RUSH内の当落ロジックには一切手を加えない。
